已完成的修改

控制平面

  • 新增控制事件账本、状态 reducer、来源覆盖、运行观察、责任关系、交接清单、回执和接管状态机。
  • 增加 Fastify API、CLI 子命令、公共导出和任务详情页的交接可见性。
  • 修正跨 1000 条事件的读取截断、责任结束状态、已确认执行者的来源信任边界，以及停止请求失败/超时后的 stop-unavailable 状态。
  • 增加幂等重放、nonce 冲突、回执目标绑定、敏感文本/路径脱敏和 payload 严格校验。

搜索与存储

  • 新增 schema v6 的 session_search 聚合投影；索引提交后刷新，事件直接变更通过 dirty 标记回退到安全扫描。
  • 保留 WAL 写入可见性、游标失效和级联删除语义，并增加回归测试。

风险与限制

  • 性能门槛未关闭：完整基准在本机索引阶段超时，不能据此宣布大数据容量通过。
  • 尚未在真实 Claude/Codex 生产日志、Windows/Ubuntu 矩阵及外部用户环境完成验证。
  • 控制平面提供可审计的观察、回执和接管边界；无法把没有可靠 stop controller 的第三方 agent 强制停止。
  • 本报告只包含实际执行结果，不将未运行的指标或平台结果视为通过。

后续步骤

  1. 在安静的基准机上重跑完整 200 MB benchmark，记录索引耗时、搜索延迟和资源峰值。
  2. 用真实 Claude/Codex 样本及 Windows/Ubuntu 运行矩阵补齐 source coverage 与 handoff roundtrip 验证。
  3. 完成 PR 审查后再决定是否把性能门槛从 HOLD 调整为 release-ready。
