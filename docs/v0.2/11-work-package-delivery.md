# 工作包 → 提交 → 文件 → 测试 → 回滚

这五项是每个增量必须能互相对应的交付信息。实际执行仍是先实现和测试，再提交、推送、评审、合并；不先提交未经验证的代码。

## 1. 拆分与合并规则

- 一个工作包交付一个可观察行为，包含使它成立的实现、测试、必要文档和兼容处理。不要把生产代码和它的必要测试拆成不同包。
- 每包一个 PR，对应 main 上一个 squash 提交。PR 内允许修正提交；提交和 PR 标题包含工作包 ID，例如 `feat(T10-B): verify captured workspace state`。
- 能独立评审不等于没有依赖。每包列出前置包与消费者；上游先合并，下游从更新后的 main 开始。一次只实施一个包，不同时堆叠多个未验证包。
- 不按文件类型机械拆分；不可独立验证的接口声明与调用方应留在同包。纯重构只有在行为保持不变且可独立验证时才单独成包。
- 扩大文件清单、接口或依赖时先更新包说明；无关工作区修改不暂存。只推送已测试提交，不直推 main，不 force push。

2026-09-14 实际仓库设置：仅允许 squash merge。因此在同一 PR 里写多个 commit 不能保证这些 commit 在 main 上可分别 revert。本规则采用一包一 PR，不改变仓库合并策略。

## 2. 每包交付卡

在 Issue 或本地任务文档先填写计划，PR 中更新实际值。未产生 SHA/PR 时明确写“未提交/未创建”，不要把拟定标题当作真实提交。

| 映射项 | 必填内容 |
| --- | --- |
| 工作包 | 唯一 ID、用户可观察结果、T/F/AC/Q、排除项、前置包、依赖它的包 |
| 提交 | 基线 SHA、分支、拟定 subject；推送后补实际 head SHA 和 PR；合并后在 PR/交接中补 main squash SHA |
| 文件 | 精确仓库相对路径，分别标记新增/修改/删除；每组文件承担的职责；必要的 schema/API/CLI 变化 |
| 测试 | 先失败的行为证据（适用时）、目标命令、通过标准、实际环境/结果、完整检查、CI 链接；人工 gate 未做须明示 |
| 回滚 | 触发条件、撤销单元、下游依赖、保留/丢失的数据、兼容前提、回滚后的测试、已演练或仅计划 |

提交 SHA 不能写进它自身的提交内容。计划文件保留拟定映射；实际提交/合并 SHA 和检查链接写入 PR 正文、交接消息或后续状态更新，不为补自身 SHA 制造递归提交。

## 3. 执行检查点

1. **定义工作包：** 核对最新 main、既有未提交改动、规格和依赖，填写交付卡。列明包完成后能验证的行为。
2. **锁定提交与文件范围：** 建立 `codex/<工作包-id>-<说明>` 分支，列出拟定提交标题和精确文件；实现与必要回归一起推进。
3. **验证：** 运行包的目标测试并检查结果，再运行 `npm run check`；运行时、公开入口、迁移或包内容改变还须 `npm run check:pack`。纯文档本地运行 `npm run check:docs` 与 `git diff --check`，远端仍执行现有完整 CI。
4. **提交、推送：** 只暂存包内文件，检查 staged diff，提交并推送分支；在 PR 填实际 head SHA、文件、测试和回滚关系。未推送只能称“本地已提交”。
5. **独立评审：** 评审者仅凭 PR、关联交付卡与规格即可检查范围、接口、数据变化、失败路径及回滚。标明真实评审者；自审不能声称外部评审。P0/P1 未解决不合并。
6. **合并与交接：** 三平台 CI 和 required check 通过后，按已授权流程 squash 合并；验证实际 merge SHA、本地/远端同步。交接列出下一包，整项任务须所有包及任务验收完成才标 done。

提交粒度太大时在开发前拆包；不要为了好看的提交历史重写已发布的 main。已经合并的 T01–T09 保持现状：例如 T09 的 PR #35 / ff32547496cd8811ed2d637ac8988611ddfaad8e 是一个整体撤销单元，无法追溯变成多个独立 main 提交。

## 4. 回滚规则

普通代码/文档使用新分支上的 `git revert`，提交逆向改动并走 PR、测试与 CI；不使用 reset/force push 重写共享历史。实际执行前通过 PR 核实目标为 main 的 squash SHA。

```bash
# 使用已核实的真实 SHA 替换尖括号；这些是操作示意，不是已执行记录。
git switch -c codex/revert-<work-package> origin/main
git revert <verified-squash-sha>
npm run check
# 涉及运行时/包内容时另运行 npm run check:pack，再提交/推送回滚 PR。
```

若 B 依赖 A，不能保留 B 而直接撤 A。先检查所有已合并消费者：可以独立撤销的下游先各自回滚；若中间状态不可运行，应在同一个回滚 PR 中按下游到上游排列撤销提交，测试最终组合，不合并失败的中间状态。其他任务也可能成为消费者，不能只看当前任务表。

代码回退不等于数据库降级。涉及 schema 的包必须列出旧代码能否读取现库；本项目旧程序拒绝较新 user_version。优先提交兼容现库的前向修复；需要数据恢复时先停服务并保留现库，在新目录恢复备份，明确备份后人工编辑的损失并另行确认。禁止删迁移文件、手改 user_version 或删库来伪装回滚成功。详见 [存储迁移](07-storage-migration.md)。

只恢复某个文件的旧版本是新的修复变更，需要重新分析接口和测试，不能自动称为“包已回滚”。回滚记录同时区分产品代码变化与用户数据影响。
