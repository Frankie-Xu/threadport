# 产品范围与功能验收

## 1. 目标用户与主场景

第一批用户是已经使用 Claude Code 或 Codex CLI、经常跨项目/分支工作的个人开发者。即使只使用一种 Agent，也应该能通过历史发现和任务整理获得价值。

核心场景：昨天处理支付回调，开过三个会话。今天搜索“支付”，找到这个任务，看到最后一次测试失败及之后的改动，检查目标与约束，在原 Agent 恢复或交给另一 Agent 开新会话继续。用户无需手工找到日志文件，也无需重新叙述完整历史。

成功的首次体验以“找到自己的真实任务并做出下一步”为准。演示数据浏览、生成 Capsule、子进程成功启动都不单独算接续成功。

## 2. 全局功能边界

**必交：F01–F10。** 所有功能都需要同时满足本文验收和质量文档的全局门槛。

首版排除：云同步、登录/计费、团队权限、GitHub Issue 双向同步、自动语义聚类、向量库、LLM 自动总结、跨机器文件同步、浏览器聊天迁移、自动 checkout/stash/reset、代码恢复点、多 Agent 并行竞赛、内嵌 PTY、MCP/ACP server 和第三方动态插件加载。

源码和 UI 默认英文，贡献与发布文档提供英文入口；本开发规格用中文。任务文本、路径和搜索必须支持中文与 Unicode。首版不引入多语言翻译系统。

## 3. 功能规格

### F01 · 首次启动与本地数据来源

**用户价值：** 不注册、不配置模型 API key 即可开始。

输入为用户允许的日志目录和项目根目录。首次启动展示将读取的来源、仅本地索引的说明，用户选择来源后才开始扫描。CLI 可通过明确的 `--source` 提供相同授权。内置人工合成的 demo 模式使用独立临时数据目录。

边界：只探测已知位置是否存在；未经选择不遍历其内容。不扫描整块磁盘、不自动读取所有 Git 仓库。不能识别路径时提供添加目录，不要求上传日志。源目录与项目目录分开配置。

**验收：**

- AC-F01-1：空安装可进入 onboarding；没有任何 Agent 时仍能打开 demo，明确显示 demo 标记。
- AC-F01-2：选择一个存在、一个不存在、一个无权限来源，各自给出状态；可修正路径重试，不让整个应用失败。
- AC-F01-3：重启保留选择；撤销来源后停止扫描并移除该来源的索引文本，用户手工任务保留且提示来源已移除。
- AC-F01-4：CLI/API 错误提示包含修复动作，不包含原始日志、密钥、完整环境变量。

审查阻断：扫描未允许的目录、demo 和真实数据混用、暗中联网或默认遥测。

### F02 · 自动发现与增量索引

识别 Claude/Codex 的候选文件，形成 SessionRecord；保存来源版本/解析版本、最后扫描时间和错误原因。来源布局以经过验证的版本 fixture 为准，不把私有日志当作稳定官方协议。

首版后台刷新：仅在本地服务运行时，每 15 秒检查已允许来源；用户可手动刷新。并发读取最多 2 个文件。JSONL 从完整行边界增量读取；文件截断、替换、inode/身份变化时重建该会话索引。扫描页显示进度、取消、失败数量和最后更新时间。

边界：不更改源文件。单文件默认最多 50 MiB，单条 JSONL 行最多 1 MiB，总规范化事件最多 100,000 条、总来源输入最多 1 GiB；超限显式跳过/停止并说明可收窄来源。超过容量不伪装成“没有更多结果”。

**验收：**

- AC-F02-1：同一输入扫描两次，Session 和 Event 的数量、ID、人工关联保持不变。
- AC-F02-2：追加两行只新增对应事件；半行不导入，补齐后恰好导入一次。
- AC-F02-3：混入坏 JSON、未知字段、未知事件类型，单条/单文件失败隔离；不会输出错误的完成状态。
- AC-F02-4：源文件删除后保留人工任务，标记会话 missing；替换/截断重建不抹掉人工目标。
- AC-F02-5：撤销、取消、进程中断后可重试，未完整提交的批次不产生重复记录。

审查阻断：全量日志一次性读进内存、按文件名跨 Agent 去重、以系统当前时间伪造源事件时间。

### F03 · 历史列表与搜索

按项目、来源 Agent、日期过滤。搜索匹配脱敏后的任务标题、人工目标、可见 user/assistant 文本片段、文件相对路径；返回匹配位置与所属任务/会话。中文连续子串可搜，英文大小写不敏感；多个词采用 AND，不提供隐含正则或 SQL 查询语法。

默认排序为最后可观察活动时间倒序，ID 作为稳定的第二排序键；日期以 UTC 存储、当地时间显示。每页默认 50 项、最多 100 项。无效/缺失时间单独显示 unknown，不使用扫描时间把旧会话顶上来。

边界：首版是文字搜索，无语义搜索和全磁盘全文检索。历史命中不代表当前结论仍有效。

**验收：**

- AC-F03-1：通过中文需求、英文片段、`src/a/index.ts` 均能定位到预设的唯一会话；重名项目可区分工作目录。
- AC-F03-2：组合过滤、清空过滤、分页往返不丢失条件；零结果给出调整条件入口。
- AC-F03-3：搜索结果、DOM、响应体中都找不到 fixture 中的密钥或隐藏推理字段。
- AC-F03-4：固定容量数据集下达到质量文档规定的查询延迟，索引时搜索仍能响应。

### F04 · 任务收件箱与人工整理

默认首页显示任务；未关联会话放「Unassigned sessions」。按同一项目显示关联建议，用户可「从会话创建任务」「加入已有任务」「移出任务」。不自动把同项目/分支的所有会话合成一个任务。

任务字段：标题、当前目标、约束、下一步、生命周期、会话列表。用户能编辑；保留修订记录和来源，不被再次扫描覆盖。任务标题必填 1–120 字符，目标最长 8,000，单条约束最长 2,000、最多 50 条，下一步最长 4,000；超限拒绝并指出字段。

生命周期由用户控制：active、paused、completed。检测到命令失败另加 attention 标记，不自动修改生命周期。已完成任务出现新日志显示“完成后有新活动”，由用户选择重开。归档仅改变列表可见性，可撤销。

边界：单会话最多属于一个任务；单任务首版限一个项目身份，可以关联该项目的多个本地 worktree。跨项目关联明确拒绝；同名分支不是同一项目身份。

**验收：**

- AC-F04-1：创建、重命名、改目标、添加/移除会话、暂停、完成、重开、归档/取消归档全部可持久化。
- AC-F04-2：扫描刷新不覆盖人工字段；每次关联/移除和任务更新发生在事务内。首版不提供一键跨任务移动，先移出到未归类再显式加入另一任务；中间状态持久化可恢复。
- AC-F04-3：两个标签页同时修改，旧 revision 返回冲突，让用户刷新/比较；不静默覆盖。
- AC-F04-4：任务详情能区分人工确认与机器派生内容；任务不存在和项目不匹配均有明确错误。

### F05 · 任务详情与可追溯状态

详情展示目标、约束、下一步、关联会话、变更文件、命令执行和失败。点击证据能定位来源事件的脱敏摘录。历史命令逐次保留，失败—成功—失败的最终结果必须为失败。不同 cwd/会话的相同命令不得粗暴相互抵消。

事实标签：observed（日志记录）、user-confirmed（用户编辑确认）、derived（规则提取）、unknown（没有依据）。计划句不等于采纳的决策，exit 0 不等于任务完成。旧测试没有对应历史文件快照时，显示“历史结果，当前有效性未知”。

边界：目标候选可从最新可见用户消息提出，但可能只是追问；未经确认标 derived。中文禁止句须保留原文并给人工约束编辑入口，不宣称自然语言约束完整提取。事件顺序优先来源序号，同时间戳不乱序。

**验收：**

- AC-F05-1：预设 `1 → 0 → 1` 命令序列最后失败；未知退出码保留 unknown。
- AC-F05-2：最后用户修正和历史原目标均能找到，人工目标有最高展示优先级。
- AC-F05-3：文件路径保留层级；同名文件、重命名、Unicode 不合并。
- AC-F05-4：证据失效/文件不存在有提示；没有证据不生成成功断言。

### F06 · 工作区验证

`validate` 继续只做 Capsule 格式验证；新增 `verify` 检查某次捕获与指定本地工作区。报告分为 matched、drifted、unverifiable，并给逐项原因、捕获时间和验证时间。匹配是“在声明范围内捕获状态一致”，不能推导业务正确或历史测试有效。

首版验证限定同一个用户绑定的本地项目及选定 worktree：比较 HEAD、tracked diff、未跟踪文件内容/路径、相关文件删除/重命名和可读性。不同 worktree 必须显式选择与确认绑定，不用绝对路径相等当作唯一身份，也不只用 remote URL 认定相同。无 Git、无初始 commit、范围超限、读取中发生变化均返回 unverifiable。

边界：不 checkout、不同步文件、不重跑日志里的测试、不执行恢复。未跟踪内容存在大文件或符号链接无法安全读取时，报告缺失范围，不能返回 matched。

**验收：**

- AC-F06-1：捕获后立即验证为 matched；改 tracked/untracked、HEAD 或删除相关文件为 drifted。
- AC-F06-2：portable root `.` 与明确绑定的绝对根目录可验证；错误项目被拒绝或 unverifiable。
- AC-F06-3：文件读取失败、仓库被移动、扫描时并发修改不会生成假 matched。
- AC-F06-4：JSON、UI 和 CLI 的结果语义一致；报告可独立保存。

### F07 · 接续预览与交接包

从任务选择目标 Agent、工作目录和接续模式。生成不可变预览，包含目标、约束、已知/未知事实、最近命令、当前验证报告、来源摘要，以及将传给目的端的**完整实际文本**。人工字段先校验、再脱敏；用户可以返回修改任务重建预览。

接续包不是会话克隆：跨 Agent 会创建新会话，同 Agent 优先用已验证的原生 resume。包不包含 hidden reasoning、认证资料、原始日志、源代码完整快照或自动执行命令。

边界：默认文本上限 32 KiB UTF-8。超限先移除较老证据摘录，列出删减；目标与人工约束不得静默截断，仍超限则要求缩短或取消。预览有效期 15 分钟；任务 revision、包摘要或工作区变化必须重新生成/确认。

**验收：**

- AC-F07-1：实际传输文本的 SHA-256 与用户确认预览一致；修改任务、文本或包文件使确认失效。
- AC-F07-2：drifted/unverifiable 不显示绿色成功；用户可以重建，或明确接受列出的不确定性后继续。
- AC-F07-3：JSON/Markdown 导出可读取；默认不覆盖，失败不留下看似完整的半包。
- AC-F07-4：导出拒绝未经脱敏的路径/密钥样例，导出清单明确是 metadata，不包含代码同步。

### F08 · 在终端实际继续

UI 提供固定形式的命令 `threadport continue --handoff <uuid>`；命令只含应用生成的 UUID，不拼接用户标题、路径或日志命令。终端再次展示目标、目录、数据将交给哪个 Agent、验证状态，然后等待用户确认。执行器使用结构化 executable/argv/cwd，`shell: false`、继承终端 stdin/stdout/stderr。

首次支持四种路径：Claude→Claude 原生恢复、Codex→Codex 原生恢复、Claude→Codex 新会话、Codex→Claude 新会话。每种能力独立记录验证版本，命令存在仅表示 installed；不确定认证状态显示 unknown，真正启动后由目的端处理登录。

边界：不统一假设 `--prompt-file`；每个 runner 根据实测 CLI 选择输入方式。CLI 帮助/版本证据必须与实现一起入 PR。无法可靠传输完整预览文本的版本只能 export-only，不能标 stable 接续。

**验收：**

- AC-F08-1：fake executable 验证 argv/cwd/stdin、退出码、信号和取消；文本中的 `$()`、引号、换行都不被 shell 执行。
- AC-F08-2：缺失可执行文件、不支持版本、登录失败、用户取消有独立结果；ThreadPort 不更改目标默认权限配置。
- AC-F08-3：四条真实路径均完成隔离测试任务，目的端保留人工约束并能做出正确下一步；保存版本、命令、结果和脱敏证据。
- AC-F08-4：非 TTY 禁止启动交互 Agent；重复运行同一已消费包不自动再启动，用户需要创建新的接续尝试。

### F09 · 可读导出与问题诊断

导出当前任务 Markdown 和接续 JSON 到用户指定目录，预览写出文件名与内容。无安装者也能阅读 Markdown，格式与源码位置不绑定。诊断仅包含应用版本、OS/arch、来源/事件数量、解析版本、错误码和时间，不含原始内容、绝对用户路径或环境变量值。

**验收：** AC-F09-1：Markdown 离线可读，事实标签与缺失清单齐全；AC-F09-2：诊断可预览后手动复制，不自动提交 Issue；AC-F09-3：错误目录、已有文件、磁盘失败保留原文件并返回 actionable error。

### F10 · 管理数据与离线可用

展示应用存储位置、索引容量、最近刷新、来源选择。提供清除索引、移除来源、重建索引、删除本地应用数据；清除前列明影响。清除索引保留人工任务和修订，删除全部应用数据必须明确确认且不碰源日志、源仓库。

本地存储不是加密保险箱；默认仅当前 OS 用户可读写，诊断与导出仍需预览。缓存支持重建；手工目标、约束和任务关联属于不可丢失的用户数据。

**验收：** AC-F10-1：断网下发现、搜索、整理、预览、导出可用；AC-F10-2：清理后源目录逐文件摘要不变；AC-F10-3：数据库迁移失败恢复原数据，重启不会静默清空数据库；AC-F10-4：重建后人工字段与会话关联仍在。

## 4. 页面与交互验收

| 页面 | 必须显示 | 主操作 | 必须覆盖的状态 |
| --- | --- | --- | --- |
| Onboarding | 来源目录、读取边界、demo | 选择来源并扫描 | 无工具、路径无效、拒绝读取 |
| Home | 搜索、任务列表、未归类会话、attention、最后刷新 | 打开/创建任务 | 初次为空、加载、部分失败、无结果 |
| Task | 人工目标、约束、状态、来源、证据、更新时间 | 继续任务 | 未知事实、失效证据、并发冲突 |
| Handoff | 目标、目录、完整预览、验证、限制 | 确认生成终端命令 / 导出 | 缺目标、漂移、过期、取消 |
| Settings | 来源、存储、版本、诊断 | 调整来源/清理 | 权限失败、迁移错误 |

按钮操作期间禁止重复提交；失败不清空编辑内容。键盘能完成创建/搜索/确认，焦点可见；状态不只靠颜色表达。1280×800、1440×900 无主要内容裁切，窄至 768 px 允许侧栏折叠；首版不承诺手机操作 Agent。

## 5. 首版用户实验

测试 5 名有目标 Agent 的外部开发者：从安装后开始计时，至少 4 人无需维护者代操作，在 5 分钟内找到自己的会话并准备接续；至少 3 人完成一次真实接续。记录具体失败点，不只问满意度。此门槛是首版可用性决策规则，不是市场规模或 10k Stars 预测。
